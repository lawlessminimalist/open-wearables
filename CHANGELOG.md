# Fork changelog

Dated entries, newest first, describing what moved and why so the next session can read this before exploring. Upstream has no CHANGELOG.md, so this file is fork-owned and never conflicts. Entries stay short; the reasoning lives in the linked files.

## 2026-09-20

The reconcile onto upstream 0.9.0 (4aa4dbf5, 45 commits) landed on `reconcile/upstream-2026-09-20`. Upstream moved the backend to Python 3.14, renamed the `energy` series to `active_energy` keeping only a string alias, split the Google provider into `health_connect` and `google_health`, added primary-lease renewal to the sync task, and gave the workout list provider and type filters, optional zones and a computed pace. Eight files conflicted, all resolved by keeping both sides except the lockfile, which was taken from upstream and re-locked with garminconnect 0.3.7.

The energy rename would have broken the app at import: the fork-owned `garmin_connect/coverage.py` referenced `SeriesType.energy` at module level, as did `data_247.py`, its coverage test and the activity-bucketing patch. All four now say `active_energy`. `fix-pace-null` was retired: upstream computes the pace itself, and its route now passes `include=` to `get_workouts`, which the patch's stale signature would have rejected on every workout list request. The symbol-level drift check flagged exactly the two methods that had changed, one of which was the rename alone; the other three patches whose files were touched were confirmed unchanged by hash, so this reconcile spent one subagent audit instead of three. Accepted change from the retirement: pace is now a one-decimal float rather than an int, and any Suunto workouts change value because upstream rejects the `1000/average_speed` derivation the patch used.

The backend test suite was not run locally: the podman machine failed to start because Homebrew's podman 6.1.2 passes `--timesync` to a krunkit 1.1.1 left behind by the November podman installer under `/opt/podman/bin`, and the fixtures need a container runtime or `TEST_DATABASE_URL`/`TEST_REDIS_URL`. The fix is a newer krunkit from the `libkrun/krun` tap, which Homebrew now refuses to load until the tap is trusted, so it was left for the user. `ty`, `ruff`, the migration guard, the registry lint, the patch install loop and the full frontend chain all passed; CI on the pull request is the gate for the suite. Upstream 1f9b1f33 now commits `docs/openapi.json` and fails CI when it is stale, so the fork regenerates it with `scripts/export_openapi.py` after every merge; the fork's copy carries the credential-provider connect endpoint that upstream lacks.

The adversarial review of the reconcile's five fork commits ran after the merge and found one deployment gap: upstream's rename shipped no migration for the stored `series_type_definition` row, so production still held id 81 as `energy` (confirmed read-only with `ow-sql`) while the enum and frontend said `active_energy`. Migration `f3a9c1d2e4b5` renames that one row, guarded on the old value. The review's other findings were consistency issues around the retired patch: a missing RETIRED banner on its file, a registry entry whose fields still pointed at the old marker and no upstream PR, an unexplained flag in `apply.py`, a dead section header in the installed guard, and a self-contradicting waiting recipe in `HARNESS-NOTES.md`. All fixed in the follow-up.

A read-only investigation found why Withings blood pressure never shows in the dashboard: the readings are ingested and stored, but the body section asks `/summaries/body` for a reading within the last four hours, the route caps the window at twenty-four, and the cuff is used once a day. Recorded in `TODO.md`.

## 2026-09-13

The agent tooling branch `chore/agent-tooling-improvements` made the drift checker symbol-aware. `check_upstream.py` now records a hash of every replaced method in `.upstream-symbols.json` when the baseline is refreshed, reports a shadow risk only when a method body changed rather than when its file was touched, and gained `--lint` and `--explain`. The new `test_ow_patches_shadow_drift.py` compares those hashes against the working tree so a merged but unaudited upstream change fails CI. The lint forbids patches over fork-owned files, which immediately retired `fix-garmin-connect-activity-hr-samples` into `garmin_connect/workouts.py`. The upstream guard hook gained a test table under `.claude/hooks/cases/`, a repo-scoped `agent_telemetry.py` hook pushes session metrics to the homelab OpenTelemetry collector, a fork-owned `ow-patches.yml` workflow runs the lint and hook tests in CI, older registry notes moved to `PATCHES-archive.md`, and this file, `TODO.md`, `.claude/HARNESS-NOTES.md` and a real `CLAUDE.md` map were added.

The telemetry hook now prices every request at published list prices and emits `ow_agent_cost_usd` by model, `ow_agent_tool_cost_usd` by the tool the request issued (split evenly when one request issued several, `none` when it issued none) and `ow_agent_unpriced_requests_total` for models missing from its `PRICING` table, so a cost is never guessed. The table is the one dhlaw-explorations read from platform.claude.com on 2026-09-03. `test_agent_telemetry.py` under `.claude/hooks/` checks the parsing, the pricing and the payload offline and runs in `make hook-test` and the `ow-patches.yml` hooks job. The agent-efficiency dashboard gained cost per session, cumulative cost by model, cost by issuing tool, an unpriced-requests stat and a cost column in the sessions table. The hook then gained a `UserPromptSubmit` idle-gap notice and `ow_agent_idle_recache_tokens_total`, `check_upstream.py` gained `--show` and `--list` behind `make patch-show` and `make patch-list`, and `.claude/bin/` gained the read-only `ow-sql` and `grafana` wrappers that a local allow rule permits. A later commit the same day added `ow_agent_subagent_tokens_total` from the Agent completion notices, since subagent transcripts are sidechains and their usage was otherwise invisible, and `HARNESS-NOTES.md` gained the zsh expansion and permission-classifier traps that an analysis of the session's tool errors surfaced.

The homelab repo gained the `agent-efficiency` Grafana dashboard (`k8s/manifests/monitoring/dashboards/`): sessions in range, tokens per session by model, tool calls per prompt, tool error share, upstream-guard denials, cumulative token, request, tool-call and result-byte series, and a per-session table, all over the `ow_agent_*` counters this repo pushes. Every panel carries turn-end counters forward with `last_over_time`; none uses `rate()`.

The homelab `openwearables-longevity` dashboard was rebuilt the same day around the Withings scale and cuff: blood pressure, arterial stiffness and body composition rows, age estimates side by side with a monthly age-gap history, and per-night and per-day source fusion in place of the sleep and activity provider selectors. The deployment's `LONGEVITY.md` in the homelab repo records the evidence and calibration for the new signals; the Body Scan nerve health scores and visceral fat are not on it because upstream's Withings provider defers those measure types.

The reconcile onto upstream 0.8.0 landed as PR #14 with 46 upstream commits. `fix-pace-null` was rebased because it had shadowed the new `name`, `entry_source` and `intensity` fields; `fix-garmin-connect-rate-limit-backoff` was retired into source after it had hidden the VO2max sync for two weeks; Garmin error classification became type- and status-based after an adversarial review found the library's typed 429 was never recognised; and merge migration `e2c0dda6e505` joined the two Alembic heads.

Two guardrails were added the same day. `block_upstream_pr.py` exists because a reconcile PR was opened on upstream's tracker by mistake (their #1611, closed within a minute). Upstream's `publish-images.yml` was gated to its repository owner and disabled on the fork, where it had failed nightly for weeks.
