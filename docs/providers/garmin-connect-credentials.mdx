<Note>
**Not sure which Garmin integration to use?** The [Garmin API Integration](/providers/garmin-api-integration) is Garmin's business program (OAuth, webhooks, approval required). This page covers the `garmin_connect` provider, which uses Garmin's **Personal API**: each person creates a key for their own account and pastes it once. It suits personal and family deployments where every account holder can create their own key.
</Note>

## Overview

Garmin's Personal API gives an account holder programmatic access to their own Garmin Connect data with a personal API key. Open Wearables stores each user's key (encrypted) on their `garmin_connect` connection, exchanges it for a 24-hour access token at sync time, and pulls their data on the usual sync schedule. There is no shared login and no Garmin developer approval.

## What syncs

| Data | Source |
|------|--------|
| Workouts, with per-sample heart rate, GPS and power | Activity search and activity details |
| Daily steps, active and resting energy, distance, floors, intensity minutes, resting heart rate | Daily summary |
| Intraday heart rate | Daily heart rate |
| Sleep sessions and stage totals | Daily sleep |
| HRV (nightly average and readings) | HRV |

Not available through the Personal API, so not synced: VO2max, intraday stress and body battery curves, and body composition. Data already stored from the earlier credentials-based integration stays.

## Setup

<Steps>
  <Step title="Set MASTER_KEY on the backend">
    Personal API keys are stored encrypted, and the backend refuses to accept a key without `MASTER_KEY` (a Fernet key). Generate one and add it to the backend's environment:

    ```bash
    python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
    ```

    ```bash
    MASTER_KEY=<the generated value>
    ```

    Keep it with your other secrets. Changing or losing it makes stored keys unreadable, so every user would need to paste a new key.
  </Step>
  <Step title="Enable the provider">
    Enable **Garmin Connect** under Settings, Providers.
  </Step>
  <Step title="Send the user their pairing link">
    On the user's page, use **Copy pairing link** and send it to them. The page lists Garmin Connect with a field for a Personal API key.
  </Step>
  <Step title="The user creates and pastes a key">
    In Garmin Connect they open **Settings, Personal API** ([connect.garmin.com/app/settings/personalApiToken](https://connect.garmin.com/app/settings/personalApiToken)), create a key (it is shown once) and paste it on the pairing page. Open Wearables checks the key with Garmin before saving it, so a mistyped key is rejected straight away.
  </Step>
</Steps>

An integration can also link a key directly: `POST /api/v1/users/{user_id}/connections/garmin_connect/api-key` with `{"api_key": "..."}`. Like the OAuth authorize endpoint, it is public; the pairing link is the credential.

## Key lifetime

Keys last 30, 90 or 180 days or a year, chosen when they are created, and Garmin emails the account holder about a week before one expires. When Garmin stops accepting a key, the connection is marked **expired** and syncing stops until the user pastes a new key through the same pairing link. A longer expiry means fewer reconnects.

## Limitations

| Limitation | Detail |
|-----------|--------|
| Personal use | Garmin intends the Personal API for individuals accessing their own data, not commercial apps serving many users. |
| No push | Data arrives on the sync schedule; there are no webhooks. |
| Coverage | VO2max, intraday stress and body battery, and body composition are not served (see above). |
| Rate limits | Not published by Garmin. A rate-limited request stops that sync run; the next scheduled run tries again. |
