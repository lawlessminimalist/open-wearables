<Note>
**Not sure which Garmin integration to use?** If you need to connect many end-users' Garmin accounts at scale, use the [Garmin API Integration](/providers/garmin-api-integration) (OAuth-based, requires Garmin Developer Program approval). This page covers the credentials-based provider — ideal for personal use, internal tools, or research where you own or control the Garmin account.
</Note>

## Overview

The Garmin Connect credentials provider pulls data directly from Garmin Connect using an email and password — the same account you use to log in to [connect.garmin.com](https://connect.garmin.com). No developer program enrollment, no OAuth, no webhook configuration.

Data is fetched on demand via the open-source [python-garminconnect](https://github.com/cyberjunky/python-garminconnect) library.

**Data types synced:**

| Data type | Details |
|-----------|---------|
| Sleep | Duration, stages (deep, light, REM, awake) |
| Heart rate | Intraday samples + resting HR |
| HRV | Last-night HRV + weekly average |
| Stress | Intraday stress level samples |
| Daily stats | Steps, active calories, distance, average stress, resting HR |
| Body composition | Weight, BMI, body fat %, muscle mass, bone mass |
| Workouts / activities | Type, duration, distance, HR, calories, elevation, pace, power |

<Warning>
**Personal use only.** The `python-garminconnect` library uses Garmin's internal Connect web API — it is not an officially supported Garmin API. Do not use this provider to sync other people's accounts without their explicit consent and understanding of how their data is being accessed. For multi-user production deployments, use the [OAuth-based Garmin provider](/providers/garmin-api-integration) instead.
</Warning>

## What you need

- A Garmin Connect account (free at [connect.garmin.com](https://connect.garmin.com))
- A Garmin device paired and syncing to that account
- The account's **email** and **password**

No API keys, no developer portal access, no approval process.

## Setup

<Steps>
  <Step title="Add credentials to your environment">
    Add the following variables to your `backend/config/.env` (or your deployment environment):

    ```bash
    # Garmin Connect credentials
    GARMIN_CONNECT_EMAIL=your.email@example.com
    GARMIN_CONNECT_PASSWORD=your_garmin_password

    # Optional: path to store the session token on disk.
    # Defaults to /tmp/garminconnect_tokens if not set.
    # Set a persistent path to avoid re-authenticating on every restart.
    GARMIN_CONNECT_TOKEN_STORE=/var/data/garminconnect_tokens
    ```

    <Warning>
    Store `GARMIN_CONNECT_PASSWORD` in a secrets manager or `.env` file that is **never committed to version control**. Treat it with the same care as a database password.
    </Warning>
  </Step>

  <Step title="Restart the backend">
    The provider is registered automatically when the environment variables are present. Restart the backend service to pick up the new credentials:

    ```bash
    docker compose restart backend
    ```

    On first startup the provider will authenticate with Garmin Connect and persist the session token to `GARMIN_CONNECT_TOKEN_STORE`. Subsequent restarts load the saved token and skip the login request.
  </Step>

  <Step title="Trigger a sync">
    Once the backend is running, trigger a sync for the target user via the API:

    ```bash
    curl -X POST "https://<your-domain>/api/v1/providers/garmin_connect/users/<user_id>/sync" \
      -H "X-Open-Wearables-API-Key: <your-api-key>"
    ```

    Or use the historical sync endpoint to backfill a specific date range:

    ```bash
    curl -X POST "https://<your-domain>/api/v1/providers/garmin_connect/users/<user_id>/sync/historical" \
      -H "X-Open-Wearables-API-Key: <your-api-key>" \
      -H "Content-Type: application/json" \
      -d '{"start_date": "2025-01-01", "end_date": "2025-03-31"}'
    ```
  </Step>
</Steps>

## How authentication works

On first use the provider calls `garminconnect.Garmin.login()` with the supplied email and password. Garmin's login flow may trigger a **two-factor authentication (2FA) challenge** if your account has 2FA enabled — see the note below.

After a successful login the session token is written to `GARMIN_CONNECT_TOKEN_STORE`. On subsequent calls the token is loaded from disk, bypassing the full login. If the session expires the provider automatically re-authenticates.

<Note>
**Two-factor authentication (2FA):** If your Garmin account has 2FA enabled, the initial automated login may fail or require manual intervention. The simplest workaround is to **disable 2FA** on the Garmin Connect account used by this provider, or use a dedicated Garmin account without 2FA enabled.
</Note>

## Limitations

| Limitation | Detail |
|-----------|--------|
| Unofficial API | Uses Garmin's internal Connect web API. Garmin may change it without notice. |
| Personal accounts only | Not suitable for connecting other users' accounts at scale. |
| No real-time push | Data is only available when a sync is triggered — there is no webhook/push delivery. |
| Historical depth | How far back data is available depends on the account's sync history in Garmin Connect. |
| Rate limits | Garmin Connect may throttle or block accounts that make too many requests in a short window. |

## Comparison: credentials vs OAuth provider

| | Garmin Connect (credentials) | Garmin API (OAuth) |
|---|---|---|
| Setup time | Minutes | Weeks (approval-based) |
| Requires developer program | No | Yes |
| Suitable for other users' accounts | No | Yes |
| Real-time push data | No | Yes |
| Official/supported API | No | Yes |
| Best for | Personal use, internal tools, research | Production multi-user apps |
